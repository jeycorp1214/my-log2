# 기능 추가 평가

> 판단 기준: mylog 핵심 가치 — Local-first, 알림 없는 자발적 기록, 간결한 UI, 20-40대 타겟
> v2: 체크리스트/칸반 재검토, dayjs→date-fns 교체 검토 반영

---

## ✅ 추가할 만한 것

### 잔디 심기 (기록 히트맵)

GitHub 잔디처럼 날짜별 기록 밀도를 색상으로 표현.

**이유**

- 강압적이지 않음. 알림 없이 성취를 시각화.
- 이미 계획된 "연간 리포트" 기능과 데이터 재사용 가능.
- expo-sqlite 쿼리 하나로 구현 가능. 외부 라이브러리 불필요.
- "오늘의 회상" 진입점으로 활용 가능.

**주의사항**

- 게이미피케이션 요소(점수, 레벨업 등) 배제. 순수 시각화만.
- 설정 탭 또는 연간 리포트 화면에 위치.

---

### 체크리스트 (독립 기능 or 메모 고도화)

날짜 연동 가능한 체크리스트. 메모 탭 내 체크박스 문법 지원 or 독립 할 일 목록.

**이유 (판단 번복)**

- 캘린더(일정) + 메모 + 체크리스트는 Notion/Apple Notes처럼 묶이는 게 자연스러운 확장.
- 현재 MemoEditor는 단순 TextInput. 마크다운 체크박스 (`- [ ]`) 파싱 추가는 최소 비용.
- logs 테이블에 `isCompleted: boolean` 컬럼 추가 시 체크리스트 아이템과 일정이 동일 구조.
- "관리" 카테고리 내 고도화로 앱 정체성 유지 가능.

**구현 범위 제안 (최소 → 확장 순서)**

1. MemoEditor에 `- [ ]` / `- [x]` 렌더링 추가 → 탭 기반 체크박스 (라이브러리 없이 파싱)
2. 독립 체크리스트: logs에 `isChecklist` 플래그 추가 → 기존 CRUD 재사용
3. 완료 목록 별도 섹션으로 분리 (캘린더 뷰와 연동)

**주의사항**

- `react-native-draggable-flatlist`는 여전히 보류. 드래그 우선순위 변경은 2단계 이후.
- 루틴 템플릿(체크리스트 세트 저장)은 체크리스트 기본 기능 안정화 후 검토.

---

### 아이젠하워 매트릭스 분류 뷰 ✅

체크리스트 아이템을 중요도/긴급도 2x2로 분류하는 뷰. 마감일 없음, 담당자 없음, 스윔레인 없음.

**판단 번복 → ✅**

스코프가 명확함. 복잡도 낮음.

**데이터 구조 (최소)**

```sql
-- todos 테이블 신규
id, title, isCompleted, quadrant, createdAt, updatedAt

-- quadrant: 'do' | 'schedule' | 'delegate' | 'eliminate'
-- (긴급+중요 | 중요+여유 | 긴급+안중요 | 안긴급+안중요)
```

**UI 구조**

```
┌──────────────┬──────────────┐
│  즉시 실행   │   계획       │
│  (긴급+중요) │  (중요+여유) │
├──────────────┼──────────────┤
│  빠르게 처리 │   제거       │
│ (긴급+안중요)│ (안긴급+안중요)│
└──────────────┴──────────────┘
```

각 셀 탭 → 해당 사분면 아이템 목록 + 추가 버튼.

**구현 비용**

- `todos` 테이블 1개 추가 (drizzle schema 편집 + migration)
- 2x2 그리드 컴포넌트 (단순 View 4분할)
- 기존 체크리스트 CRUD 재사용
- 외부 라이브러리 불필요
- **체크리스트와 별개 테이블** — logs와 섞지 않음 (성격 다름)

**주의사항**

- 사분면 간 이동: 탭 후 사분면 선택 모달. 드래그 앤 드롭 X (1단계).
- 완료 아이템 별도 섹션 or 숨김 처리.

### 사진 일기 결합 (날짜별 대표 사진) — 보류

> 사용자 판단으로 현재 보류.

캘린더 각 날짜에 사진 첨부. 리텐션 강하지만 용량 관리 복잡도 높음.

---

### 타임라인 뷰 (수직 뷰)

현재 캘린더 뷰 외에 하루 기록을 시간 순으로 수직 나열하는 뷰.

**이유**

- 현재 아코디언 목록의 시각적 업그레이드. 코드 재사용 가능.
- 특정 날짜 탭 시 진입하는 형태로 자연스러운 UX 연결.
- react-native-reanimated 이미 설치됨. 구현 비용 낮음.

**주의사항**

- 별도 탭이 아닌 날짜 셀 탭 → 슬라이드업 시트 형태 추천.
- 시간 단위 일정이 없는 앱이므로 "시간축" 없이 단순 세로 나열.

## ❌ 추가하면 안 되는 것

### React Native Paper

**이유:** Gluestack v3 + NativeWind 이미 사용 중. UI 라이브러리 이중 설치 = 번들 증가 + 스타일 충돌 리스크.

---

### react-native-draggable-flatlist

**이유:** 체크리스트 1단계(마크다운 파싱)에서는 불필요. 2단계 독립 체크리스트 구현 후 재검토.

---

### date-fns 교체 — 보류

**상황:** dayjs 현재 14개 파일, ~50개 호출. date-fns 미설치.

**교체 비용 분석**

| 항목           | 상세                                                                                          |
| -------------- | --------------------------------------------------------------------------------------------- |
| 편집 파일      | 14개 (`utils/date.ts`, `utils/repeat.ts`, 컴포넌트 12개)                                      |
| 포맷 토큰 변환 | `YYYY`→`yyyy`, `D`→`d`, `DD`→`dd` — silent bug 위험                                           |
| 체이닝 변환    | `dayjs(d).year(y)` → `setYear(d, y)` 등 함수형으로 재작성                                     |
| `fromNow()`    | `formatDistanceToNow(d, { locale: ko, addSuffix: true })`                                     |
| 번들 이득      | dayjs ~6KB gzip. date-fns tree-shakeable이지만 이 앱 사용 함수 ~15개 → 이득 미미 or 역전 가능 |

**결론: 보류.**

- 포맷 토큰 하나 놓치면 날짜 렌더링 silent bug.
- 번들 이득 불명확.
- 현재 dayjs 코드 정상 동작 중.
- 교체 원한다면 `utils/date.ts` 단독 래퍼화 후 내부만 교체 — 그래도 이득 낮음.

---

### 루틴 템플릿

**이유:** 체크리스트 기본 기능 미구현 상태. 기반 없이 추가 불가. 체크리스트 안정화 후 재검토.

---

### 연속 달성 스트릭 (Streak)

**이유:** 핵심 가치 "알림 없는 자발적 기록"과 직접 충돌. 스트릭은 매일 켜야 한다는 강박을 유발. 타겟 유저(조용히 관리하고 싶은 사람)와 정반대 방향.

---

### 성장형 캐릭터 / 식물 키우기

**이유:** 앱 컨셉(담백한 관계 기록)과 맞지 않음. 간결한 UI 원칙 위반. 구현 비용 대비 컨셉 적합도 낮음.

---

### Time Blocking (드래그 앤 드롭)

**이유:** 체크리스트 → 캘린더 변환 기능. mylog에 체크리스트 없음. 전제 조건이 없어 구현 불가.

---

### '미룬 일' 모아보기 / 복잡한 칸반

**이유:** 단순 status 3컬럼은 OK (위 조건부 참고). 드래그/스윔레인/담당자 등 복잡한 칸반은 앱 정체성 붕괴.

---

### 플로팅 타이머

**이유:** 집중 시간 측정 = 생산성 앱 기능. 관계 기록 앱과 무관. 앱 범위 확장 비용만 발생.
